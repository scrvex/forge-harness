# Forge plugin — scripts registry (Core 1, v1.2.0)

All run with Python 3.12 from inside a project (any folder with `forge.json` above the cwd); the plugin folder is
found from the script's own location. `<plugin>` = the folder printed by the SessionStart brief. 0 tokens unless
marked *Ollama* (GPU minutes, 0 $). Everything removed in 0.6.0 (metrics, bench, queue, retro, verify2, release,
relayout, manifest, dashboard, draw_*, pdf2text, serve, skills installer, instantiate) lives in `C:/ai/FORGE_0.3` and git history.

## Skills map maintenance (K32–K33)
- **Where:** `domains.json` (plugin root) is the single source; `forge-route` holds only the index table (a test checks that it
  names every domain and every primary skill of it).
- **Check what is available** (each cycle audit, `forge-audit` §9): save the session's skill list (`name: description` per line)
  → `skills_map.py audit --available-file list.txt --md <tech>/docs/SKILLS_INVENTORY.md`. Statuses: Installed & Tested (evidence
  file `state/skill_tests/<domain>.md` from a real run, with a line `RESULT: PASS`) · Installed, Not Tested · Requires
  Configuration (a tool neither on PATH nor in its standard install folder) · Partly available · Unavailable. Disk-only runs cannot see app/Cowork skills, and skills
  listed without a description cannot be compared for overlaps - the report says both.
- **Add or replace a skill:** `vet` (REJECT / REVIEW / LOW-RISK; static checks cannot prove safety) → read the SKILL.md → the
  owner's yes → install (marketplace or plugin, never `curl | sh`) →
  give it ONE role in `domains.json` (a stage's `skill` or the `support` menu; a `conflicts` rule if it overlaps) → bump the plugin
  version → tests. Projects never edit the map; they propose in `docs/KERNEL_PROPOSALS.md` (K18).
- **Diagnose:** a skill that did not load → `audit` shows it missing; a wrong domain → fix triggers (Cyrillic words are stems:
